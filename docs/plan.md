# План разработки Gridlume 1.0

Составлен 2026-10-28 по макету (`design/mockup`) и решениям (`decisions.md`).
Каждый этап заканчивается **рабочей версией**, которой можно пользоваться на ваших машинах
(`calibur`, `junk`, сервер Timeweb). Следующий этап начинается после вашей проверки.

## Главные правила

- **Каждый этап — законченная польза.** Не «полпрограммы», а версия, которая уже что-то делает хорошо.
- **Сначала смотреть, потом управлять.** Действия, которые что-то меняют, появляются только после того,
  как отображение надёжно и понятно.
- **Лёгкость — требование, а не пожелание.** Бюджеты проверяются автоматически:
  ядро ≤ 50 МБ памяти на 20 узлах, агент ≤ 15 МБ и ≤ 1% процессора в простое,
  первая загрузка интерфейса ≤ 400 КБ (сжато), схема из 200 узлов — 60 кадров в секунду при перемещении.
- **Два языка с первого коммита.** Ни одной строки текста в коде — только ключи словарей.
- **Дизайн-система из макета — единственный источник** цветов, отступов, шрифтов и компонентов.

## Устройство

```
gridlume/
├── cmd/
│   ├── gridlume/          ядро: веб-интерфейс + API + база, один файл
│   └── gridlume-agent/    агент на машинах
├── internal/
│   ├── store/             SQLite (миграции), позже PostgreSQL за тем же интерфейсом
│   ├── graph/             узлы, связи, места, уровни, зависимости, «что сломается»
│   ├── api/               HTTP + WebSocket для интерфейса
│   ├── auth/              вход, сессии, код первого запуска, 2FA, роли
│   ├── agentlink/         связь с агентами: подключение, привязка, команды
│   ├── metrics/           метрики и их сжатие со временем
│   ├── problems/          проверки, перепроверка, группировка по причине, события
│   ├── notify/            Telegram, MAX, Яндекс Мессенджер, email, webhook
│   ├── changes/           журнал изменений, «было / стало», откат
│   ├── vault/             хранилище паролей, импорт KeePassXC
│   ├── integrations/      Keenetic, Timeweb, Docker (через агента), NUT (ИБП)
│   └── i18n/              тексты сообщений ядра (уведомления, ошибки)
├── agent/                 код агента: метрики, Docker, логи, терминал, обновление
├── web/                   интерфейс: React + TypeScript + Vite + React Flow
│   └── src/design/        токены и компоненты, перенесённые из макета
├── design/mockup/         макет — остаётся как эталон
├── docs/
└── deploy/                скрипт установки, systemd, Docker-образ
```

### Технологии

| Часть | Выбор | Почему |
|---|---|---|
| Ядро и агент | Go 1.26, стандартный `net/http` | один файл без зависимостей, лёгкая сборка под amd64 и arm64 |
| База | SQLite через `modernc.org/sqlite` (без CGO), режим WAL | собирается под любую платформу без компилятора C |
| Связь с агентом | WebSocket поверх TLS, агент подключается сам, ключи Ed25519 | работает за любым NAT, на машине не нужно открывать порты |
| Метрики машины | `gopsutil` + чтение счётчиков сетевых карт | без лишних демонов |
| Docker | Docker Engine API через сокет (на агенте) | не нужен Docker CLI |
| Терминал | PTY через WebSocket | терминал в браузере |
| Пароли | Argon2id + XChaCha20-Poly1305 | современная стойкая схема |
| Обновления агента | подписанные сборки (minisign/Ed25519), откат при ошибке | безопасно и автоматически |
| Интерфейс | React 19, TypeScript, Vite, `@xyflow/react`, раскладка ELK | самая зрелая библиотека нодовых схем |
| Состояние интерфейса | Zustand | лёгкое, без лишних обёрток |
| Языки | i18next с ICU-форматом | множественные числа в русском («1 узел, 2 узла, 5 узлов») |
| Стили | CSS-переменные из `tokens.css` + CSS-модули | без UI-китов |
| Тесты | `go test`, Vitest, Playwright для сквозных проверок | |
| Сборка и проверки | GitHub Actions: линтеры, тесты, бюджеты памяти и размера, сборка | каждая ветка проверяется автоматически |

## Этапы

### Этап 0 — Основа

Скелет проекта, на котором дальше всё строится.

- Структура папок, модули Go, приложение Vite, `gridlume dev` — ядро и агент локально одной командой.
- Перенос дизайн-системы из макета в `web/src/design`: токены, кнопки, бейджи, узел, связь, диалог, подсказка, скроллбары.
- Словари RU/EN, переключатель языка.
- GitHub Actions: линтеры, тесты, сборка, проверка бюджетов.
- `CONTRIBUTING.md`, шаблоны задач и pull request'ов.

**Готово, когда:** `gridlume dev` открывает пустой экран Gridlume в новом дизайне на двух языках, проверки на GitHub зелёные.

### Этап 1 — Карта (версия 0.1)

Можно нарисовать всю инфраструктуру руками, и она сохраняется.

- Первый запуск: одноразовый код в консоли → создание администратора; вход, сессии.
- База: места, узлы, связи, уровни, раскладка.
- Схема: места цветными областями, узлы, связи с описанием «что это и зачем», вход внутрь машины, хлебные крошки, мини-карта, поиск.
- Добавление вручную: роутер, VPS, домен, устройство; связи между ними.
- Карточка узла и связи (без живых данных): обзор, заметки, связи, «что сломается, если…» по вручную заданным зависимостям.
- Экран «Все узлы».

**Проверка на ваших машинах:** рисуем деревню, дом и Timeweb, как в макете.

### Этап 2 — Агент и живые данные (версия 0.2)

Машины появляются на схеме сами, цифры живые.

- Агент: установка одной командой с кодом, привязка, автоматическое переподключение.
- Метрики: процессор, память, диски, температура, сеть; графики за 14 дней со сжатием.
- Docker: контейнеры, их состояние и ресурсы, compose-проекты — машина «изнутри» строится сама.
- Связи из Docker: общие сети, порты, переменные с адресами → предложения «похоже, api обращается к postgres» (подтверждает человек).
- Живые связи: трафик по счётчикам сетевых карт, точки по линиям, «идёт / должна быть», задержка и потери.
- Обновление агентов из ядра: автоматически или кнопкой, с откатом.

**Проверка:** ставим агента на `calibur`, `junk` и сервер Timeweb.

### Этап 3 — Проблемы и уведомления (версия 0.3)

Если что-то не так — видно сразу и приходит одно понятное сообщение.

- Проверки: ping, TCP, HTTP(S), сроки сертификатов и доменов.
- Движок проблем: перепроверка (в том числе с другой машины), учёт зависимостей, одна причина — одно сообщение, сообщение о восстановлении.
- Строка состояния, центр проблем, события, советы.
- Присмотр: агенты проверяют соседей — тревога придёт, даже если упадёт машина с ядром.
- Telegram; правила уведомлений простыми фразами; тихие часы.

### Этап 4 — Понимание (версия 0.4)

Схема объясняет, а не только показывает.

- «Что сломается, если…» по реальным зависимостям, подсветка через уровни.
- Путь запроса (сначала задаётся вручную, затем — по наблюдаемым соединениям).
- Шаблоны объяснений для известных программ: PostgreSQL, nginx, Redis, Home Assistant и т. д.
- Журнал изменений: агент замечает смену образа, compose-файлов, перезапуски; «что изменилось перед сбоем», «было / стало».
- История: шкала за сутки, режим «смотрю прошлое».
- Слой «Что видно из интернета»: открытые порты по пробросам на роутере и проверка снаружи.

### Этап 5 — Действия (версия 0.5)

Управление — безопасное и объяснённое.

- Логи в реальном времени, фильтр ошибок.
- Терминал машины в браузере.
- Запуск, остановка, перезапуск контейнеров; откат изменений compose.
- Единое подтверждение: что произойдёт, риск, ввод имени для опасного, журнал действий с откатом.
- Быстрые команды (Ctrl+K).

### Этап 6 — Интеграции и защита (версия 0.6)

- Хранилище паролей, импорт из KeePassXC.
- Keenetic: клиенты сети, порты, проброс портов, трафик.
- Timeweb Cloud: серверы, баланс, домены.
- Поиск устройств в сети (ARP, порты, производитель).
- ИБП через NUT: заряд, запас времени, план выключения и включения по зависимостям.
- Резервные копии: расписание, проверка восстановлением.
- MAX, Яндекс Мессенджер, email, webhook.

### Этап 7 — Готово для людей (версия 1.0)

- Установщик «без запар»: скрипт и Docker-образ, мастер первой настройки.
- HTTPS: автоматический сертификат по IP и Let's Encrypt для домена; 2FA обязательна при открытии наружу.
- Резервная копия базы самого Gridlume, миграции, проверка обновления с версии на версию.
- Проверка безопасности, нагрузочные тесты (200 узлов), документация на русском и английском.
- Публичный репозиторий, CLA, первые релизы на GitHub.

## Как работаем

- **Ветка на этап:** `stage/0-foundation`, `stage/1-map` и т. д.; внутри — короткие ветки на задачи.
- **Pull request на каждый этап** с описанием и снимками экрана; слияние в `main` после проверки.
- **Проверка на живых машинах:** каждую сборку я ставлю на `calibur` через SSH и прохожу сценарии этапа;
  вы смотрите интерфейс и даёте замечания.
- **Решения** продолжаем записывать в `decisions.md`, отказ от чего-либо — с причиной.

## Риски

| Риск | Что делаем |
|---|---|
| Объём большой, можно утонуть | каждый этап самостоятельный; лишнее переносим в следующий, а не растягиваем текущий |
| Автоматические зависимости ошибаются | всегда предлагаем, а не утверждаем: «похоже, связаны — подтвердите» |
| Роутер Ростелекома без API | ручной узел + проверка доступности; уточнить модель |
| API Keenetic (XML/RCI) неудобен | отдельный модуль интеграции, проверим на вашем роутере |
| Ограничения в РФ (Telegram, зарубежные сервисы) | несколько каналов уведомлений; всё работает без внешних сервисов |
| Один ноутбук на 6 ГБ | бюджеты памяти проверяются автоматически на каждом изменении |
